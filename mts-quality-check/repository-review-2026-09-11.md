# MTS Quality Check 저장소 검토 — 2026-09-11

`mts_quality_check`의 `cdqc`는 **설계 방향이 명확하고 계산 기반이 갖춰진 v0.5 연구용 라이브러리**다. 기존 구조를 유지하면서 점수 계산의 경계 조건과 실제 데이터 검증을 보강하는 것이 적절하다. 운영 판정에 활용하기 전에는 입력 좌표의 정확성, 정상 기준의 재현성, 실제 오측정에 대한 성능을 확인해야 한다.

이 문서는 소스 검토, 실행 검증, 기존 스펙에 기록된 관찰을 구분하여 정리한다. 검토 과정에서 프로젝트 코드는 수정하지 않았다.

## 1. 현재 구현의 역할과 구조

`cdqc`는 TEM CD 측정 좌표, 이미지, 세그멘테이션에서 피쳐를 추출하고, 기준 집단 대비 이상 점수와 판정 보조값을 계산한다. CD는 측정 대상의 치수(Critical Dimension)를 뜻한다.

| 계층 | 관찰 단위 | 주요 역할 |
|---|---|---|
| L3 | 개별 CD | 길이·위치·방향·시퀀스 잔차와 이미지 엣지 증거 계산 |
| L2 | 측정 시퀀스 | CD 개수, 각도·피치·길이 요약 등 시퀀스 전체의 변화 관찰 |
| L1 | 이미지 전체 | 이미지 단위의 품질·분포 변화 관찰 |

핵심 계산은 배열·데이터프레임을 받아 결과를 반환하는 함수 중심으로 구성되어 있다. 파일 로딩과 배치 흐름은 `scripts/run_batch.py` 등에서 다루며, 계산 결과를 실제 합격·불합격으로 해석하는 정책은 사용자 측에서 정하도록 분리했다.

피쳐의 의미, 이상 방향, 사유 코드를 registry에 모았고, 중앙값과 MAD를 이용한 정규화, 상위 피쳐 점수 집계, 물리 단위 임계값 비교를 제공한다. MAD는 중앙값 기준 절대편차의 중앙값으로, 극단값의 영향을 줄여 분포의 퍼짐을 추정하는 통계량이다.

## 3. 유지할 만한 설계

- **계산과 판정 정책의 분리:** 피쳐 추출·정규화 결과를 보존하면서 공정별 기준을 별도로 적용할 수 있다.
- **계층별 관찰:** 개별 측정의 국소 오류와 시퀀스 전체의 변화, 이미지 단위 문제를 나눠 볼 수 있다.
- **피쳐 메타데이터의 중앙 관리:** 의미·이상 방향·사유 코드가 모여 있어 점수 해석과 확장이 수월하다.
- **통계적 경계 조건에 대한 고려:** MAD가 0인 경우의 하한, 유효 표본 수, 원형 각도, 결측 피쳐 수를 다루는 기반이 있다.
- **검증과 미결 사항의 기록:** 합성 주입 테스트와 스펙에 설계 이유·한계를 남겨 후속 개발의 근거로 활용할 수 있다.

이 구조를 크게 바꾸기보다 기존 API의 의미를 일관되게 만들고 입력에서 점수까지의 신뢰성을 보강하는 편이 효율적이다.

## 4. 재현한 계산 오류

아래 세 문제는 소스 검토와 작은 입력으로 재현했다. 코드 예시는 해당 검토 커밋의 동작을 나타내며, 이후 수정 버전에서는 결과가 달라질 수 있다.

### 4.1 이미지가 없을 때 불필요한 이상 점수가 생김

`extract_l3(None, ...)`는 기하 피쳐만 계산하는 경로를 지원한다. 그러나 이미지가 없으면 `edge_valid_s/e`를 `False`로 채우고, 점수 계산은 이를 엣지 검증 실패로 해석해 각각 고정 점수 `4.0`을 부여한다.

```python
import numpy as np
import cdqc

s = np.column_stack([np.zeros(10), np.arange(10.) * 10])
e = s + [10., 0.]
l3 = cdqc.extract_l3(None, s, e, 1.)
scores = cdqc.aggregate_z(cdqc.cohort_z(l3))
print(scores[["z_max", "z_top2_kth"]].drop_duplicates())
# z_max = 4.0, z_top2_kth = 4.0
```

이미지 증거가 없는 상태와 실제로 엣지 검증에 실패한 상태를 구분해야 한다. 단순히 결측값으로 바꾸는 것만으로 충분한지는 bool 변환과 집계 경로까지 확인해야 한다.

관련 코드: `cdqc/features/l3.py:64`, `cdqc/api.py`의 `apply_z`.

### 4.2 L2 각도 점수에 180도 주기 처리가 빠짐

L2의 `angle_median`은 원형 중앙값을 계산하지만, 기준 통계와 비교하는 점수 경로에서는 일반 뺄셈을 사용한다. 기준 `89.9°`와 평가값 `-89.9°`는 180도 주기로 보면 차이가 `0.2°`인데, 큰 차이로 계산되어 최종 점수가 상한 `30`까지 올라간다.

```python
import numpy as np
import pandas as pd
import cdqc

df = pd.DataFrame({"angle_median": [89.9] * 10 + [-89.9]})
z = cdqc.cohort_z(df, base_mask=np.arange(11) < 10)
print(z["z_angle_median"].iloc[-1])  # 30.0
```

원형 변수에 맞는 기준 중심·산포·잔차 계산을 일관되게 적용해야 한다. 수정 시에는 경계 양쪽의 가까운 각도와 실제 큰 회전이 각각 올바르게 처리되는지 확인해야 한다.

관련 코드: `cdqc/api.py:354`의 일반 차이 계산과 `cohort_stats`의 기준 통계 계산.

### 4.3 그룹 카테고리가 결측이면 정규화가 중단됨

그룹 키에 결측값이 있으면 `groupby` 기본 동작이 해당 행을 제외한다. 이후 원래 전체 인덱스를 다시 붙이는 단계에서 행 수가 달라져 예외가 발생한다.

```python
import pandas as pd
import cdqc

df = pd.DataFrame({
    "category": ["a", "a", None],
    "cd_nm": [10., 10., 10.],
})
cdqc.cohort_z(df, ["category"])
# ValueError: Length mismatch:
# Expected axis has 2 elements, new values have 3 elements
```

결측 그룹을 별도 그룹으로 계산할지, 사전에 명확한 입력 오류로 거부할지 정책을 정해야 한다. 행 보존과 통계 기준의 의미를 함께 검증할 필요가 있다.

관련 코드: `cdqc/normalize.py:165`의 그룹화 및 결과 인덱스 복원.

## 5. 운영 적용 전에 확인할 부분

### 실제 오측정에 대한 성능은 아직 확인되지 않음

`cdqc_spec.md:423`에는 기존 검증이 **정상 이미지 12장짜리 한 세트와 인위적 오류 주입**에 한정된다고 기록되어 있다. 이는 기존 프로젝트 문서에 남은 검증 이력이며, 이번 검토에서 해당 원본 데이터를 다시 실행한 결과는 아니다.

현재 테스트는 구현의 일관성과 상상한 오류에 대한 반응을 확인하는 데 유용하다. 실제 불량의 재현율, 정상 데이터의 오경보율, 오류 위치를 정확히 찾는 비율은 라벨된 실제 데이터로 별도 측정해야 한다. 다른 레시피·배율·카테고리에 대한 일반화도 아직 주장할 수 없다.

### 배치 간에 재사용할 정상 기준이 필요함

`scripts/run_batch.py:247`은 L3에서 제외 카테고리를 뺀 입력으로 기준 통계를 다시 계산하고, L2에서도 현재 입력으로 통계를 계산한다. 정상으로 확인된 데이터와 평가할 데이터를 분리해 운영하는 흐름이 필요하다.

이대로 배치를 평가하면 불량이 기준에 섞여 점수를 낮추거나, 배치 구성에 따라 동일한 측정의 점수가 달라질 수 있다. 라이브러리에는 기준 통계 반환과 `apply_z`를 통한 재사용 기능이 있고, 주입 테스트도 고정 통계를 사용한다. 이를 일반 배치 평가에 연결하여 기준 데이터·파라미터·버전을 함께 관리하는 것이 좋다.

### 약 −1px 오프셋의 원인을 먼저 규명할 필요가 있음

`cdqc_spec.md:427`에는 여러 카테고리의 delta 중앙값이 약간 음수이며, 약 −1px의 계통 오프셋이 미결 사항으로 남아 있다. 픽셀 중심 규약의 차이인지, 모델의 편향인지는 확인되지 않았다.

실제 파일의 픽셀 크기, 단위, 좌표 원점, 축 방향, 픽셀 중심 규약을 이미지 오버레이와 대조해야 한다. 입력 변환의 오차가 남아 있으면 후속 피쳐와 임계값을 조정해도 그 오차를 보정하는 방향으로 맞춰질 수 있다.
